How it works

From a file to finished records in four steps

An admin describes the document once. After that, every upload follows the same path: extract, stage, review, commit.

  1. 01

    Build a template

    Choose which objects to create, which fields to fill and how the records relate. Start from a bundled Document Kit or from a blank template.

  2. 02

    Upload a document

    Drop a file into the Document Intake tab. It is stored as a standard Salesforce File, and a background job reads it with your org's Einstein generative AI.

  3. 03

    Review every value

    Extracted values wait in a staging area. A reviewer can edit or clear any of them, pick a record type, and decide whether to reuse a matching record.

  4. 04

    Commit the records

    One click inserts or updates everything in a single transaction. If any record fails, nothing is saved and the reason is shown on screen.

What you get

Built for the records, not just the text

Pulling words off a page is the easy part. DocToRecords handles what comes after: field types, related records, duplicates and permissions.

Multi-object templates

One document can create several related records, such as an Account, a Contact and a Case, linked the way your data model expects.

Typed, not just text

Values are converted to the target field's type: dates, numbers, checkboxes and picklist values that exist in your org.

Duplicate matching

Matching rules find records that already exist, so the reviewer can reuse or update them instead of creating a second copy.

Review before write

Nothing reaches your business objects until a person has seen it. Every correction is kept alongside the original extracted value.

Respects your permissions

Every query and write runs as the current user. Nobody can read or change data through DocToRecords that they could not touch directly.

Test before you trust

Each Document Kit ships with sample documents and answer keys. Run them in your own org and see the score before going live.

Security and data

Your documents never leave your Salesforce org

DocToRecords has no server of its own. The only processing outside the record is a call to your org's own Einstein generative AI, made through Salesforce's documented Prompt Builder path and governed by your Einstein Trust Layer settings.

Read the security page Ask for the security pack

Architecture overview, Salesforce Code Analyzer report and scanner findings, sent on request.

  • Sharing enforced. Every Apex class runs with sharing. None are global.
  • CRUD and field-level security. Queries run WITH USER_MODE and writes run as the user, with describe checks before every save.
  • No injection surface. Object and field names are resolved against the schema. Every value is a bind variable.
  • No credentials. No Connected Apps, Named Credentials, Remote Site Settings or stored tokens.
  • Standard storage. Documents are Salesforce Files. Staged data sits in custom objects inside your org.
  • One permission set. Access is granted explicitly. No profile or org setting is changed.

Questions

What teams ask first

What does my org need?

Einstein generative AI enabled, with Prompt Builder available. DocToRecords uses only standard objects and APIs and needs no other package.

Do I need Health Cloud?

No. DocToRecords works in any org with Einstein generative AI, including plain Sales Cloud and Service Cloud. It also works alongside Health Cloud if you have it.

Where does my document go?

It is stored as a Salesforce File in your org and processed by your org's own Einstein generative AI. DocToRecords makes no HTTP callouts and sends nothing to Qasmin or any third party.

Can it handle documents with health information?

DocToRecords adds no new processor: data stays in Salesforce and goes only to your own Einstein service. Whether that is suitable for protected health information depends on your agreements with Salesforce and how your Trust Layer is configured, so confirm it with your compliance team.

Who pays for the AI usage?

Each extraction uses your org's Einstein generative AI. Salesforce bills that usage to you under your own agreement. Qasmin does not resell or mark it up.

Does it ever save records on its own?

No. Extraction only fills a staging area. Records are written when a reviewer chooses to commit, and only the fields that reviewer is allowed to write.

Is it on AppExchange?

Not yet. Today it is installed directly from an install link, starting in a sandbox. The full security documentation is available on request.
